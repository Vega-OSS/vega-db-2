# Architectural & Implementation Decisions

This log documents decisions made during implementation where the specification was ambiguous or required design clarification. Format: What, Why, Date.

- **Self-Contained Local Implementation (No External Vega-OSS):** Implemented all WiscKey storage engine components (arena allocator, skiplist, bloom filter, buffer pool, sstable, manifest, vlog, engine, services, cli, bench) directly within the local `vegadb` Go module rather than importing from `github.com/vega-oss/vega-db`. This eliminates external repository dependencies, simplifies supply-chain provenance, and guarantees 100% local build and test execution (2026-10-04).
- **Initial Git & Branch Setup:** Created empty root commit on `main` to provide a valid merge-base for `feat/wisckey-engine` commit inspection scripts (2026-10-04).
- **Gosec G115 Compliance in DecodeEntry:** Verified non-negative bounds and converted unsigned uvarint length after comparison against max integer constraints to safely eliminate integer overflow warnings without sacrificing parsing performance (2026-10-04).
- **Merge Iterator Key Cloning:** Block buffer iterator slices are recycled back into `bufpool` as iterators advance. Cloned entry keys (`bytes.Clone`) upon inserting items into the 2-level merge heap to avoid referencing recycled memory buffers during multi-way merges (2026-10-04).
- **Flush & Compaction Version Refcounting and Serialization:** Background flushes and compactions both modify the LSM version state. Added `compactMu` mutex and explicit version reference counting (`v.Ref()` / `v.Unref()`) around version installations to prevent concurrent race conditions from dropping newly flushed L0 tables (2026-10-04).
- **Crash Recovery Replay Boundary (`immTail`):** Snapshotting `vlog.Tail()` at active memtable freeze time into `readState.immTail` ensures torn-tail truncation and crash recovery replaying from flushed vlog offsets never skips records committed to the active memtable while flush was in progress (2026-10-04).
- **Pipelined Scan Prefetching:** Implemented a concurrent worker pool with a 64-item sliding window for range scans in `internal/engine/scan.go`. This decouples sequential key traversal in the LSM tree from random disk I/O when resolving value log pointers, achieving high scan throughput without blocking on individual disk seeks (2026-10-04).
- **Default Engine Store:** Wired `engine.Open` as the default store for `vegaserver` (`--store=engine`), fulfilling production persistence requirements while keeping `--store=memory` as an optional flag for ephemeral testing (2026-10-04).
